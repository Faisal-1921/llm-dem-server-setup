## test-api

| | |
|---|---|
| 功能 | 按 control 约定调用 DeepSeek：`json_object`，`temperature=0`，确认账号与模型可用 |
| 入口 | `lem_dem/mapping.py` |
| 输入 | 无；读项目根 `.env` |
| 默认出口 | `runtime/outputs/R_05_deepseek_mapping/R_00_api_connectivity.json` |
| 依赖 | DeepSeek；`DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` |

占位符 `your_deepseek_api_key_here` 视为未配置，直接失败。产物只写模型名、用量和是否成功，**不写密钥**。

```bash
python run.py test-api
```

## graph

| | |
|---|---|
| 功能 | 按 Excel `01_Node_Library`–`04_All_Solid_Paths` 建立四层有向图：26 个 B/M/P/C 节点、32 条实线兼容边、5 条 C8 虚线。每个节点/边仍有独立 JSON Schema |
| 入口 | `lem_dem/knowledge_graph/graph.py` |
| 源表 | `data/knowledge_graph/source/LEM_market_node_reference.xlsx` |
| Schema 库 | `data/knowledge_graph/schemas/nodes/`、`data/knowledge_graph/schemas/edges/` |
| 默认出口 | `runtime/outputs/R_20_knowledge_graph/`（`G01_market_node_reference.json`、Mermaid、schema 索引） |

四层：报价 B → 撮合 M → 定价 P → 分配/出清 C。主流同机制路径 22 条；全图实线路径 57 条（用于连边审计，不作推荐模板数）。

```bash
python run.py graph
```

## schema-prompt

| | |
|---|---|
| 功能 | 给其它 Agent：一篇文章抽出若干条规则 |
| Prompt 全文 | `data/prompts/market_rule_schema_types.prompt.md` |
| JSON Schema | `data/knowledge_graph/schemas/prompt/LearnedRules.schema.json` |
| 类型 | `MarketRule` = `MarketNode` + `RuleRelation[]` |

其它 Agent 把 Prompt 全文当系统提示，输出 `{ "rules": [...] }`。每条规则带定义和与其他规则节点的关系。

| | |
|---|---|


## graph-web

| | |
|---|---|
| 功能 | 只读知识图谱可视化页（图例 + 分层有向图 + Schema 检视） |
| 入口 | `python run.py graph-web` → `lem_dem/knowledge_graph/web.py` |
| 页面 | `lem_dem/knowledge_graph/static/index.html` |
| HTTP 出口 | `http://127.0.0.1:8766/`（本机需 SSH 隧道） |
| 绑定 | **仅** `127.0.0.1:8766`（禁止 `0.0.0.0`；不要占用监控页 8765） |
| PID | `/home/zhouyx/tmp/v0.3-graph-web.pid` |
| 日志出口 | `runtime/outputs/R_20_knowledge_graph/graph-web.log` |
| 读入 | `G01_market_node_reference.json`（缺则从 Excel 01–04 生成） |

接口清单与隧道命令见 [A-server-interfaces/graph-web.md](../A-server-interfaces/graph-web.md)。

```bash
source /home/zhouyx/miniforge3/etc/profile.d/conda.sh
conda activate project
```
